# 优化过程与归档证据

## 决策与证据

| 观察或约束 | 采用的设计与判断 | 已有验证 | 结果与边界 |
|---|---|---|---|
| 分类与两份检测模型均含卷积，分别实例化计算核心会增加资源 | 用同一物理 PE、共享算术服务与执行计划运行三个配置 | 当前 RTL/BD、模型描述符及最终资源报告 | 支持4×8×8及1×8×32映射；最终整机DSP148。没有同特性独立三阵列基线，不报告虚构资源节省率 |
| INT8与16位激活混用，需要保持数值合同 | W8A8/W8A16，DSP共享激活双乘法打包及A16字节分解 | 量化策略、QDQ/ORT对照；舍入流水定向仿真与当前DUT哈希闭合 | 主机量化精度可查；最终160/256板端完整精度尚未归档。128是PE内DSP数，整机为148 |
| 宽位舍入和运算流水影响时序/资源 | 缩窄有界幅值段，保留高位丢失溢出条件与接口流水深度 | round历史比较：两个流各175,194输出比较；DUT/helper哈希匹配现存源码 | 源码声明减少位数不能当作实测物理FF节省；最终时序为+0.047ns，不按该结果反推单项优化收益 |
| DMA指针/credit组合判断与流控存在关键路径 | 注册并维护非空标志与credit边界，逐周期核对公共输出 | dma历史定向等价比较、覆盖文件、波形及DUT哈希 | 定向行为证据，不等于形式证明、整网回归或单项性能收益 |
| MaxPool源行存储的可变索引写入影响存储推断 | 将32位样本成对存入64位源字，以单写地址模式组织 | bulk/scalar分别23/15案例，各472 Golden像素，逐周期比较与最终源码哈希 | 历史候选验证不提供独立资源/时序实测；当前最终报告展示整机结果 |
| CPU标量整网耗时较长 | 用PL共享NPU执行网络，PS做预处理/后处理和控制 | 维护者确认同板三组推理耗时 | 三模型各一张标量117s、NEON双核11.0s、本系统3.5s；约33.4倍/3.14倍。原始逐次日志未归档，不给统计显著性或FPS |
| Linux普通分配器与PL固定地址可能冲突 | 启动预留256MiB no-map，内核独占驱动与用户态单实例任务所有权 | 设备树/驱动代码、boot验证脚本及已归档驱动加载日志 | 避免仅根据Linux启动成功推断NPU完成接入；新无日期路径未有独立板测收据 |
| 资源优化可能增加控制集、破坏布局 | 在验收中同时检查资源、控制集与最终布线时序，否决只凭声明位数的建议 | 原始maxpool历史review包含RESET-remap失败记录；最终完整routed报告 | 失败案例只作决策过程，不作为最终同版本资源对比表，不把旧工程数据混入 |

本次材料保留最终布线报告及若干模块优化的定向验证记录。未保留足以证明同一整机特性范围、同一工具阶段的完整优化前后报告对，因此不报告整机资源削减百分比。已确认的性能对比采用同平台三组板端推理时间，最终资源与时序单独列示。

本仓库布局阶段LUT46,222、FF45,376与布线阶段LUT46,278、FF45,385属于同次构建不同阶段，不是优化前后收益；顶层综合仅1,003 LUT、1,074 FF且含OOC黑盒，不能作完整整机“优化前”基线。其他历史硬件工程的资源和WNS不能替代本版基线。

## 当前尚缺的材料

1. 原PetaLinux project-spec/rootfs配置、FSBL/U-Boot/BIF启动链生成配置，或者公开可取得的匹配基础SD镜像及哈希；本地WIC存在但无公开获取入口。
2. 三模型最终160/256输入的逐张输入、Golden输出、板端输出及对比；完整整网RTL回归和波形。
3. 最终冷启动、模型DDR回读、三模型切换/停止/恢复、摄像头/HDMI的原始串口或服务日志；新路径部署版本的板测收据。
4. 原始性能测量日志、次数和起止点定义；当前仅有用户确认的近似实测耗时，不应捏造样本量、均值和方差。
5. 同一项目、相同功能与工具阶段的硬件优化前完整资源与时序报告。没有这组材料时保留上表“未形成配对归档”。
6. ResNet最初FP32到QDQ的量化生成器及校准/环境记录；原始源产物已有，缺少该生成步骤。
7. 数据集、模型权重、第三方源码、工具生成文件及随包二进制的来源、版权归属与再分发条件。
